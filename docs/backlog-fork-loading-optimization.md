# 备忘：长对话撤回/重发等待耗时与加载反馈体验优化

> 记录时间：2026-09-15  
> 状态：待启动（已记入 Roadmap，等待后续指令推进）

---

## 1. 问题背景与痛点描述

在当前实现中，消息撤回（Recall）和气泡编辑（Rewrite）的底层机制均依赖于宿主官方的 `sessions.fork` RPC 能力：
- 需要在指定的目标事件序号（targetSeq）前最后一个闭合回合（`turn/end`）处截断历史；
- 复制目标之前的全部事件树并生成新会话；
- 归档旧会话，并将工作区切换至新会话并自动提交后续操作。

### 核心痛点：
1. **长对话耗时明显**：当会话包含大量回合、海量 token 或复杂工具调用轨迹时，事件树深且大，`fork` + 数据克隆 + 磁盘 flush 过程需要等待较长时间（数秒甚至更长）；
2. **界面缺乏进度反馈（静默等待）**：当前在用户点击气泡「确定」或底部「发送」后，前端缺乏显式的 Loading 加载中状态、Spinner 旋转动画或进度文字反馈，界面处于短暂停顿状态，容易导致用户误以为界面卡死，甚至发生二次点击触发重复请求。

---

## 2. 拟定优化方向与技术方案

### 2.1 界面交互层（UI / UX Feedback）——高优先级
1. **按钮进入 Loading & 防抖禁用**：
   - 气泡编辑框的「确定」按钮在点击后立即变为 Loading 旋转态（Spinner），并设置 `disabled`；
   - 底部输入框发送按钮同样在撤回提交过程中锁定禁用，杜绝重复触发并发 fork。
2. **轻量进度与状态提示**：
   - 气泡编辑区域或正在修改条上方显示明确的过渡微文案（如：*“正在构建分支会话，请稍候...”* / *“Creating new branch...”*）；
   - 视觉模式（simple / minimal / info）下统一保持优雅的过渡呼吸动效。
3. **超时保护与异常兜底**：
   - 若 fork 接口超过预期阈值（如 15 秒）未响应，弹出友好轻提示并恢复按钮可操作态，避免永久转圈。

### 2.2 性能与异步调度优化（Performance Investigation）
1. **耗时链路分析**：
   - 通过全链路日志打点分析耗时集中在：
     - A. 后端 `/bubble/recall` 边界查找（已高度优化为单次从后向前遍历）；
     - B. 官方 `ctx.sessions.fork` 内部实现（深拷贝及事件持久化）；
     - C. client 侧 `openSession` 切换与 React 树重建。
2. **乐观体验感知**：
   - 评估是否可以在后台 fork 的同时，前端先进入平滑转场动画，缩短用户感官上的“空白等待时间”。
